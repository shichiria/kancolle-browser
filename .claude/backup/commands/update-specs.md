# /update-specs — 変更仕様書を既存SPECに統合

`docs/SPEC/changes/` にある日付付き仕様書を読み、既存の `docs/SPEC/` ファイルに反映した後、変更ファイルを削除する。

## 手順

### 1. 変更ファイルの確認

`docs/SPEC/changes/` 内の `*.md` を一覧表示する。なければ「統合対象なし」と報告して終了。

`$ARGUMENTS` が指定された場合はそのファイルのみ対象。

### 2. 各変更ファイルの処理

変更ファイルごとに:

1. 変更ファイルを読み込む
2. 「既存SPECとの関連」セクションから反映先を特定する
3. 反映先の既存SPECファイルを読む
4. 変更内容を既存SPECの適切なセクションに統合する:
   - 新規セクション → 追加
   - 既存セクションの更新 → 上書き/マージ
   - 既存内容と矛盾 → 最新の変更ファイルを正とする
5. 反映先がない場合（新機能で既存SPECに該当なし）→ 新規SPECファイルを作成し `SPEC.md` 索引にも追加

### 3. 反映内容の報告

変更ファイルごとに以下を報告:

```
## 統合結果

### YYYYMMDD_topic.md
- **反映先**: docs/SPEC/xxx.md
- **操作**: セクション追加 / セクション更新 / 新規ファイル作成
- **変更箇所**: 
  - 「データ構造」セクションにXXXを追加
  - 「ロジック」セクションのYYYを更新
```

### 4. ユーザー確認

統合結果を報告し、削除してよいか確認する。

### 5. 変更ファイルの削除

ユーザーが承認したら `docs/SPEC/changes/` から処理済みファイルを削除する。
全ファイル処理後、`changes/` ディレクトリが空であれば残しておく（次回用）。

## Rules
- 既存SPECの構造・文体に合わせて統合する
- 変更ファイルの内容を機械的にコピーしない。既存SPECの文脈に馴染むよう編集する
- 既存SPECの無関係なセクションは変更しない
- 削除前に必ずユーザー確認を取る
- SPEC.md 索引は新規ファイル作成時のみ更新
