# Extract Knowledge & Spec

GEMINI/ と LOG/ の会話ログから2種類の情報を抽出し、対応するドキュメントを更新する。
抽出完了後、処理済みファイルは各フォルダ内の backup/ に退避する。

## 抽出対象の分類

### A. ドメイン知識 → `docs/KNOWLEDGE/`

ゲーム仕様に関する事実。コードを読んでも分からない「なぜそうなっているか」の根拠。

| カテゴリ | 例 |
|---------|-----|
| ゲーム仕様 | APIフィールドの意味、計算式、閾値、艦種判定ルール |
| データ構造 | HP配列のインデックス、装備タイプID、マスターデータのフィールド名 |
| ゲームロジック | 戦闘フェーズ順序、任務条件、遠征条件、OASW判定 |
| エッジケース | 連合艦隊のオフセット、月境界の扱い、四半期年トラップ |
| UI座標/表示 | ゲーム画面の座標系、スプライト配置、ノード分類 |

### B. 設計・実装情報 → `docs/SPEC/`

アプリケーションの設計方針・アーキテクチャに関する情報。

| カテゴリ | 例 | 対応SPECファイル |
|---------|-----|-----------------|
| DTO構造/リファクタリング計画 | ParsedApi enum構成変更、DTO分割方針 | api-intercept.md, architecture.md |
| テスト戦略 | テストデータ構築パターン、カバレッジ方針、フィクスチャ管理 | test-strategy.md |
| ロギング/可観測性 | ログレベル方針、カバレッジ対象、フィルタ設定 | architecture.md |
| ビルド/型推論パターン | Rust型注釈の必要箇所、コンパイルエラーの傾向 | test-strategy.md |
| モジュール構成変更 | ファイル分割、ディレクトリ再編成 | architecture.md |
| API処理パイプライン | 新エンドポイント追加、ハンドラ実装方針 | api-intercept.md |
| オーバーレイ設計 | ウィンドウ構成、表示制御フロー | overlay.md |
| 同期/永続化 | ファイル構造変更、同期対象追加 | drive-sync.md, architecture.md |

### C. 抽出しない

- ツール・環境のトラブルシューティング (環境固有で再現性なし)
- 単純な開発起動ログ (`npm run tauri dev` のみ)
- git操作・改行設定等のインフラ作業

## 手順

### 1. 既存ドキュメントの把握
- `docs/KNOWLEDGE/README.md` を読み、ドメイン知識のカバー範囲を把握
- `docs/SPEC/SPEC.md` を読み、設計書の構成を把握

### 2. ログの走査
- `GEMINI/*.md` と `GEMINI/*.txt` を走査（backup/ 内は対象外）
- `LOG/*.md` を走査（backup/ 内は対象外）
- `$ARGUMENTS` が指定された場合はそのファイル/フォルダのみ対象
- 各ファイルの内容を分類A/B/Cに振り分ける（1ファイルが複数カテゴリに該当可）

### 3. ドメイン知識の抽出 (分類A)

1. 抽出した知識が既存KNOWLEDGEファイルに**既に記載済み**でないか確認
2. 重複は追加しない。既存の記載が不完全な場合は補完
3. 既存ファイルのトピックに該当 → 該当ファイルに追記
4. 新規トピック → 新ファイルを作成
5. `docs/KNOWLEDGE/README.md` の一覧も更新

KNOWLEDGEファイルには**事実・仕様のみ**を記載する（実装コードは含めない）。
出典がGeminiのレビュー回答の場合、ゲーム仕様として正確か判断して記載する。
不確かな情報は `※未検証` を付記する。

### 4. 設計情報の反映 (分類B)

1. 該当する既存SPECファイルを読み、現在の記載内容を確認
2. レビュー内容が**既に反映済み**（コード変更済み）の場合 → SPECの記述を現状に合わせて更新
3. レビュー内容が**未実施の計画**の場合 → SPECに「計画」として記載（実施済みと混同しない）
4. 既存SPECのどのセクションに該当するか判断し、適切な場所に追記/更新
5. 該当するSPECファイルがない場合 → 新規作成し `docs/SPEC/SPEC.md` の索引も更新

SPECファイルは**設計の意図と方針**を記載する。コードの写しではなく、「なぜそう設計したか」を重視。

### 5. 処理済みファイルの退避
- 抽出が完了したファイルを各フォルダ内の backup/ に移動:
  - `GEMINI/*.md` → `GEMINI/backup/`
  - `GEMINI/*.txt` → `GEMINI/backup/`
  - `LOG/*.md` → `LOG/backup/`
- backup/ フォルダがなければ作成
- 次回実行時に再走査されないようにする
